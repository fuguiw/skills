# doc-draft

帮用户在动笔前定好读者、目的、结构和写作风格，再按用户提供的材料起草初稿。默认停在结构这一步：用户确认结构后才写正文。初稿写完交给 doc-lint 检查。

起草的主要风险是补出看似合理、却没有依据的内容。第 4 节的规则优先于其他所有要求。

## 1. 问清楚

在一条消息里问以下问题，允许简写回答；能从请求或材料中看出的，不再问：

1. 文档类型：方案或决策、调研或对比、现状与计划，还是其他。
2. 主要读者是谁，他们已经知道什么。
3. 读者读完后要做出什么判断或行动。这决定开头写什么。
4. 有没有模板、范例或必须遵守的格式。
5. 篇幅、时间等约束。

请用户把手上的材料都给出来，不必整理：文件、链接、笔记、讨论记录、数据。读完材料后，针对缺口提出不超过 10 个编号问题，允许回答“不知道”或“待定”。能问到边界情况和取舍、不用再解释基础时，信息就够了。

不主动搜索外部资料；需要时先征得用户同意，用到的来源写进文档。

## 2. 定结构和写作约定（停下来确认）

按文档类型选骨架，再按材料调整。章节名可以改，每节的作用不能丢。

**proposal（方案、决策）**

1. 结论：要做什么决定，推荐哪个方案，主要代价。
2. 背景与问题：为什么现在要决定，不决定会怎样。
3. 方案对比：候选方案、比较维度、各自的取舍。
4. 推荐方案：怎么做、影响范围、谁负责。
5. 风险与回退。
6. 待定事项：需要谁、在什么时候决定什么。

**research（调研、对比）**

1. 结论：一句话结论、可信度、主要未核实项。
2. 问题与范围：调研什么，不调研什么。
3. 发现：按问题组织，不按来源组织；多个对象对比时用表格。
4. 依据：来源，以及是否核实。
5. 未核实与后续。

**status（现状、计划）**

1. 摘要：做到哪一步，下一步做什么，需要谁做什么。
2. 已完成：结果和依据。
3. 进行中与阻塞。
4. 下一步：顺序（已定还是建议）和负责人。
5. 风险与待决。

其他类型：开头回答“读者读完后要做的判断”，后面各节给出依据。

把以下内容发给用户确认：

- **写作约定**：读者、目的、语气（例如“简洁的工程说明，不解释行业常识”）、术语表（同一概念只用一个叫法）、状态写法（已定、建议、待确认、已实现、待验证）。
- **骨架**：每节的标题、一句话说明本节回答什么，以及材料是否足够（够，或缺什么）。

用户只要结构时，按骨架建文件，每节写一句占位说明，然后停下。

## 3. 写初稿（确认后）

- 文件位置按用户指定；未指定时询问。项目对目录或 frontmatter 有约定时，遵循项目约定。
- 在 frontmatter 中写入 `audience`、`purpose`、`doc_type`（proposal、research、status 或 other），doc-lint 会据此检查。项目约定不允许新增字段时，把写作约定写在正文开头。
- 先写不确定性最大的一节：方案写推荐方案和方案对比，调研写发现，现状与计划写下一步。开头的结论或摘要最后写，但放在最前面。
- 不超过 5 节的文档一次写完；更长的文档先写核心一节给用户看，确认方向后再写其余部分。
- 修改时只替换相关段落，不重新输出全文。请用户说明要改什么；用户直接改过的地方，当作风格偏好用到后续章节。

## 4. 不编造

- 状态、数字、负责人、决定、日期和对比结论，都必须来自用户的话或提供的材料。找不到依据时，写成【待确认：……】并列入待确认清单。
- 用户没提到的风险、替代方案和边界情况，不作为事实写进正文。可以在“待定事项”或报告中列为“候选（待确认）”。
- 推断要标明，例如“（推断：……）”，不写成事实。
- 保留用户的情态和限定：“倾向”“建议”不能写成“决定”；“大约”“目前”“在……范围内”照写。

## 5. 起草时就遵守的写作规则

- 每节先给结论，再给依据。
- 句子有主语和动作，不写电报体，不堆名词。
- 用具体动词和数字，少用形容词。
- 不用“这不是……，而是……”式的先否定再强调，不用“值得注意的是”等引导语和“赋能”“闭环”“抓手”等口号。
- 同一概念的叫法与术语表一致；技术名词、产品名和标识符保持原有拼写。
- 写明状态：已定、建议、待确认、已实现、待验证。
- 不写不提供信息的“总结”“展望”章节。

完整的写作规则见 doc-lint。

## 6. 收尾

1. 用 doc-lint 检查初稿，并告诉它这是刚起草的文档。用户提供了材料、且可以使用 sub-agent 时，按 doc-lint 的读者测试检查遗漏，标准答案从材料出，不从初稿抄。没有 doc-lint 时，按第 5 节自查一遍。
2. 向用户报告：
   - 文件位置；
   - 待确认清单：所有【待确认】、推断和候选项；
   - 读者测试结果（如果做了）；
   - 1–3 条建议的下一步。
