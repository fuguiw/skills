# 读者测试

检查读者只读文档，能否答对关键问题，并在预期的位置找到答案。它测的是可读性和前后一致，不测事实是否正确；对细微的情态变化（如“建议”变成“应”）也不灵敏，不能代替对照修改前后差异的复核。

## 1. 先写标准答案

- 出 5–8 题。每题写明：问题、标准答案、答对必须保留的限定（如“是建议，不是已定”“由运维执行”）、答案应出现的章节。
- 答案的来源：润色时用修改前的原文；起草时用用户提供的材料，不从初稿里抄。从文档里抄出的答案，测不出文档漏了什么。
- 覆盖：至少 1 题问结论或建议；至少 2 题问状态或情态（建议还是已定，已实现还是待验证，推测还是事实）；文档写了执行人时，1 题问谁来做；1 题问范围、条件或限制。
- 用中性问法，不在题目里预设答案。例如不问“文档建议的顺序是什么”，改问“后续顺序是已定的还是建议的，具体是什么”。

## 2. 让没有上下文的读者作答

起一个新的 sub-agent，只给它读者身份、文档的绝对路径和题目，不给标准答案、原文或材料。读者身份按目标读者设定，例如“负责审批这个方案的技术负责人，懂相关技术，没有参与讨论”。

```
你是<读者身份>。你只有这份文档：<绝对路径>。只读这个文件，不打开其他文件，也不用文档以外的知识。
逐题作答，并写出依据的章节。文档没有写的，答“文档未说明”，不要猜。
<题目>
最后列出：文档中有歧义的地方；前后矛盾的说法；文档默认读者已经知道、但你作为这个读者并不知道的内容。
```

没有 sub-agent 时跳过测试并说明，不要自己作答：当前会话已经知道答案，正是测试要排除的偏差。

## 3. 评分

- 每题判为：对；部分对（主要意思对，但漏了或弱化了必须保留的限定）；错（与标准答案矛盾，或会误导读者）；文档未说明。
- 答对了、但依据的章节与预期不同，单独标出。这说明结构有问题，例如结论只能从后文推出。
- 读者的答案与标准答案不一致时，先核对标准答案本身是否有误。

## 4. 修改与重测

- 错：改掉导致误读的句子。润色时出现“错”，多半是改稿改偏了，先对照原文恢复原意。
- 部分对、文档未说明：润色时恢复原文中的限定或内容；起草时补上材料里有的内容，材料里也没有的标“待确认”。
- 位置不对：章节内部的直接调整；跨章节的列入结构建议。
- 读者指出的歧义和矛盾：按原文或材料修正。对“默认读者已经知道”的内容，只补充目标读者确实不知道的部分，避免越改越长。
- 通过标准：没有“错”，“部分对”和“文档未说明”合计不超过 1 题。没有通过时，修改后换一个新的读者、用同一套题再测一次；两轮后仍未通过的，写进报告。
